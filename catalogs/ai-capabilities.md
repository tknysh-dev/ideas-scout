# Каталог можливостей AI-провайдерів

**Це базовий зріз від 2026-07-28.** Ведеться агент-ревізор (PLAN.md, Фаза 5, ще не реалізований): 1–2 прогони/тиждень, дельти проти цього зрізу, джерела — лише офіційні (docs.claude.com, anthropic.com/news, сторінка цін Anthropic, платформа/changelog OpenAI, release notes десктоп-застосунків).

**Правило датування:** кожен запис — обов'язково з датою перевірки. Застарілі записи не видаляються, а позначаються `(застаріло, перевірити)` — так ревізор бачить, що саме змінилось, а не лише поточний стан.

**Для чого цей файл:** аналітик звіряє з ним критерій 3 «Реалізовність наявними засобами» (config/criteria-passive-income.md) — чи можна побудувати конкретну ідею тим, що вже є (Mac M1 постійно, M5 опційно, підписки Claude Code і Codex CLI), і чи вкладається докупка в поріг €100. Записане тут напряму визначає коди `CAPABILITY_GAP` і `CAPITAL`.

**Рішення власника (2026-07-29, `logs/decisions.md`):** десктоп-застосунки Claude і ChatGPT, встановлені на окремому ізольованому Standard-акаунті macOS на M1 (уже існує), — це цільовий шар **виконання** вже схвалених ідей, а не другорядна деталь. Тому обидва розділи «Десктоп» нижче навмисно ведуть підрозділи з машинним ім'ям (`anthropic/desktop/<тема>` / `openai/desktop/<тема>`), на які записи реєстру посилаються полем `missing_capabilities` — нова десктоп-можливість тут є найімовірнішим тригером ревізора для оживлення `CAPABILITY_GAP`-відхилень (докладніше — `config/prompts/revisor.md`, `config/prompts/analyst.md`).

## Anthropic

### API

- **Моделі — актуальна лінійка.** Claude Fable 5 (`claude-fable-5`) — найпотужніша, завжди доступна модель, для найважчих задач і довгих автономних прогонів; Claude Opus 5 (`claude-opus-5`) — основна робоча модель для складного агентного кодування; Claude Sonnet 5 (`claude-sonnet-5`) — баланс якості й ціни, майже на рівні Opus у кодуванні; Claude Haiku 4.5 (`claude-haiku-4-5`) — найшвидша й найдешевша. **(2026-07-28, docs.claude.com — модельний каталог)**
- **Розмір контексту.** У Fable 5, Opus 5 і Sonnet 5 влазить до приблизно мільйона токенів за раз — це десятки тисяч рядків тексту чи коду в одному запиті. У Haiku 4.5 контекст менший — приблизно 200 тисяч токенів. Максимум відповіді (скільки модель може згенерувати за раз) — до 128 тисяч токенів у старших моделей. **(2026-07-28, docs.claude.com)**
- **Ціни за мільйон токенів (вхід/вихід).** Opus 5 — $5 / $25; Sonnet 5 — $3 / $15 (є вступна знижка $2 / $10 до 2026-08-31); Haiku 4.5 — $1 / $5; Fable 5 (найдорожча, найпотужніша) — $10 / $50. Це ціна саме за виклик API — якщо колись механіка буде ганяти модель на потоці поза межами підписки Claude Code, рахунок піде саме за цими тарифами. **(2026-07-28, сторінка цін Anthropic)**
- **Дешевий пакетний режим.** Batch API (запити не потребують миттєвої відповіді) коштує вдвічі дешевше за звичайний виклик — придатний, якщо колись знадобиться масово прогнати багато знахідок через LLM не в реальному часі. **(2026-07-28, docs.claude.com)**

### Десктоп

- **`anthropic/desktop/cowork-files`** — Claude Cowork: агентний режим у десктоп-застосунку Claude (окремий продукт від Claude Code, але той самий "двигун" під капотом, без термінала). Здатен довести багатокрокову задачу до кінця самостійно: читати, писати й створювати файли в дозволених теках, перейменовувати пачками, перетворювати купу документів у зведений звіт. Доступно на платних планах (Pro/Max/Team/Enterprise) у Claude Desktop для macOS і Windows (web і мобільна версія — у беті). **Що це дає для делегування:** механіку «зібрати таблицю з кількох джерел» чи «звести пачку файлів у звіт» можна доручити напряму — Claude сам відкриє потрібні файли й доведе задачу до готового документа, без написання окремого скрипта під кожну дрібну задачу. **(2026-07-29, support.claude.com — «Get started with Claude Cowork»)**
- **`anthropic/desktop/computer-use`** — керування комп'ютером у Cowork (дослідницький препрев'ю, тобто рання й нестабільна версія функції): Claude сам клацає мишею, друкує і відкриває довільні застосунки — не лише браузер, — орієнтуючись за скріншотами, так само як людина за екраном. Доступно лише на Pro/Max, лише в десктоп-застосунку macOS/Windows. Умова роботи: Мак має не спати, але Claude може працювати, поки власника немає за екраном. Обмеження: складні задачі часом виконуються лише з другої спроби; повільніше за пряме підключення через API/MCP; чутливі застосунки (банкінг, медичні сервіси, крипто) заблоковано за замовчуванням, можна додати й свій блок-лист. **Що це дає для делегування:** це саме той механізм, що потрібен для «монтажу відео» чи «операцій у браузері» з рішення власника — Claude буквально керує застосунком-редактором чи браузером на екрані M1, а не через окремий API-виклик. **(2026-07-29, support.claude.com — «Let Claude use your computer in Cowork»)**
- **`anthropic/desktop/mcp-connectors`** — MCP-конектори у Cowork: підключення сторонніх сервісів (Google Calendar, Slack, GitHub, Linear, Notion тощо) або в один клік як готовий "конектор", або вручну через довільний MCP-сервер. **Що це дає для делегування:** може сам працювати з файлами і сторонніми сервісами — тобто йому можна доручити, скажімо, регулярне складання таблиці з даних кількох джерел (звести нотатки з Notion і задачі з GitHub в один звіт), без ручного зведення вручну. **(2026-07-29, support.claude.com — «Use connectors to extend Claude's capabilities»)**
- **`anthropic/desktop/scheduled-tasks`** — заплановані задачі в Cowork: задачу можна поставити на повторення за розкладом. Локальні сесії (ті, що працюють з файлами чи браузером просто на самому Маку) виконуються лише поки Мак не спить і застосунок відкритий — пропущений через сон запуск виконується одразу після пробудження. Віддалені сесії (без потреби в локальних ресурсах Мака) крутяться на серверах Anthropic і працюють, навіть коли Мак спить чи застосунок закритий. **Що це дає для делегування:** механіку «щоночі зібрати звіт» можна доручити напряму вбудованому розкладу Cowork — але для задач, які не потребують саме локального Мака, це вже частково перекриває наявну систему launchd-скриптів (`docs/operations.md`), тож вибір «свій cron чи вбудований розклад Cowork» — окреме рішення для кожної механіки. **(2026-07-29, support.claude.com — «Schedule recurring tasks in Claude Cowork»; «Claude Cowork architecture overview»)**
- **`anthropic/desktop/permission-modes`** — три режими дозволів регулюють, наскільки без нагляду діє Claude: Manual (питає перед кожною дією), Auto (діє без питань, але блокує чутливі дії — доступ до нових тек, видалення файлів, створення розкладу), Skip (не питає й нічого не перевіряє автоматично). **Що це дає для делегування:** це і є регулятор ризику для ізольованого акаунта M1 — режим Skip потрібен саме для «без людини біля екрана», але він же найризикованіший, тож для кожної делегованої механіки варто явно вирішувати, який режим прийнятний. **(2026-07-29, support.claude.com — «Use Claude Cowork safely»)**
- Claude Code desktop — той самий "двигун", що й Cowork, але фронтенд під код (термінал, git-діфи прямо в застосунку) замість некодових задач; технічний бік (headless-режим `claude -p`) уже описано в розділі «Агентні можливості» нижче. Для десктоп-делегування важливе саме розмежування: Cowork — для «зроби мені файл/звіт/таблицю», Claude Code desktop — для «внеси мені зміну в код». **(2026-07-29, claude.com — «Navigating the Claude desktop app: Chat, Claude Cowork, Claude Code»)**

### Агентні можливості

- **Робота з інструментами (tool use).** Claude вміє викликати визначені розробником функції (кастомні tools) і вбудовані серверні інструменти — пошук в інтернеті (`web_search`), завантаження сторінки за URL (`web_fetch`), виконання коду в ізольованому контейнері (`code_execution`), робота з файлами. Це саме те, на чому побудовані збирач і аналітик системи. **(2026-07-28, docs.claude.com — Tool Use overview)**
- **MCP (Model Context Protocol).** Claude Code вміє підключати зовнішні джерела даних та інструменти через MCP-сервери (наприклад, доступ до браузера, Linear, файлових ресурсів) — саме так цей інструмент сам підключений до Chrome, iOS-симулятора, Linear тощо в поточному середовищі. **(2026-07-28, docs.claude.com)**
- **Тривалі автономні прогони.** Claude Code підтримує headless-режим (`claude -p` — прогін без інтерактивного діалогу, разовий виклик з промптом) — саме такий режим потрібен для запуску збирача й аналітика через launchd/cron без участі людини. Є task budgets (бюджет токенів на задачу, щоб агент сам розрахував темп роботи і не обірвався на півслові) і компакція контексту (автоматичне стиснення історії розмови, коли вона наближається до ліміту вікна). **(2026-07-28, docs.claude.com — Claude Code, Task Budgets, Compaction)**
- **Керування комп'ютером (computer use).** Claude вміє робити скріншоти та керувати мишею/клавіатурою — може імітувати людину в браузері. Технічно доступно, але в цій системі не заплановане (збирач працює через RSSHub/скрапінг, а не через візуальне керування браузером). **(2026-07-28, docs.claude.com)**

### Ліміти підписок

- **Claude Code — ліміти на підписці, не на прогін.** Підписка Claude (Pro/Max) дає обмежену кількість використання за ковзне вікно (типово 5-годинне вікно плюс тижневий ліміт) — не пряму оплату за токен, а квоту повідомлень/токенів у часі. Headless-прогони (`claude -p`) споживають ту саму квоту, що й інтерактивна робота — це критично для системи: якщо власник активно працює в Claude Code вдень, а джоби збирача/аналітика йдуть вночі, вони діляться одним пулом ліміту підписки. **(2026-07-28, docs.claude.com — не підтверджено остаточно, чи headless-прогони мають окремий облік від інтерактивних; перевірити окремо)**
- **Немає підтвердженого точного числа "скільки прогонів на день" для конкретного тарифу Claude Code** — офіційна документація описує механізм ковзних вікон, але не публікує фіксовані числа повідомлень на тариф так відкрито, як OpenAI. **(2026-07-28, не підтверджено, перевірити на platform.claude.com/docs — сторінка "Usage limits" chatgpt-style)**

## OpenAI

### API

- **Моделі — актуальна лінійка (2026-липень).** Флагманська лінійка GPT-5.6: **Sol** (найпотужніша, $5 / $30 за мільйон токенів вхід/вихід), **Terra** (баланс, $2.50 / $15), **Luna** (дешева, $1 / $6). Є також попередня лінійка GPT-5.5 і GPT-5.4 (зокрема дешеві GPT-5.4 mini за $0.75/$4.50 і GPT-5.4 nano за $0.20/$1.25) та спеціалізована модель для агентного кодування GPT-5.3-Codex ($1.75/$14). **(2026-07-28, developers.openai.com/api/docs/pricing)**
- **Розмір контексту.** У GPT-5.6 та GPT-5.4-родини влазить приблизно 1 мільйон токенів вводу (аналогічно Claude) — але понад поріг ~272 тисячі токенів у GPT-5.5/5.4 ціна за токен подвоюється (це "довгий контекст" з надбавкою). У GPT-5.6 довгоконтекстна надбавка теж є (Sol: $10/$45 понад поріг). Максимум відповіді — до 128 тисяч токенів. **(2026-07-28, developers.openai.com/api/docs/pricing)**
- **Кешування вводу.** Повторний ввід (той самий контекст у наступному запиті) коштує суттєво дешевше — знижка на кешоване читання приблизно 90% від базової ціни вводу, запис у кеш дорожчий за звичайний ввід (аналогічно механізму Anthropic). **(2026-07-28, developers.openai.com/api/docs/pricing)**

### Десктоп

**Важливий контекст датування:** 2026-07-09 OpenAI об'єднав десктоп-застосунок macOS — Chat, Work і Codex тепер один застосунок (стара версія лишилась окремо як "ChatGPT Classic"); одночасно офіційна довідка більше не описує окрему функцію "ChatGPT agent" — замість неї рекомендовано ChatGPT Work. Тобто станом на 2026-07-29 «агентний режим» ChatGPT — це Work, а не окрема кнопка з назвою Agent. Окремо, агентний браузер-застосунок Atlas планово припиняє роботу 2026-08-09 — його браузерні агентні можливості переносяться напряму в ChatGPT/Codex. **(2026-07-29, help.openai.com — «Moving to the new ChatGPT desktop app»; «Evolving Atlas into ChatGPT for browser-based agentic work»)**

- **`openai/desktop/work-mode`** — ChatGPT Work: агентний режим для довгих багатокрокових задач — шукає інформацію, працює через під'єднані застосунки й файли, доводить справу до готового документа/таблиці/презентації/сайту, лишаючись над проєктом годинами й самостійно розбиваючи його на кроки, з можливістю стежити за прогресом і схвалювати важливі дії по дорозі. Доступність за тарифом: Pro/Pro Lite/Enterprise/Edu отримали першими, Plus і Business — слідом; на Free і Go Work недоступний. **Що це дає для делегування:** прямий аналог того, що власник хоче доручати десктоп-агенту — «склади таблицю з кількох джерел», «зроби звіт», «постав сайт-трекер» — без написання скрипта самому. **(2026-07-29, help.openai.com — «ChatGPT Work and Codex»; openai.com — «ChatGPT is now a partner for your most ambitious work»)**
- **`openai/desktop/browser-agent-transition`** — керування браузером зараз у перехідному стані між продуктами: колишній Operator (окремий продукт 2025) керував браузером через аналіз скріншотів (модель "Computer-Using Agent"), потім це влилося в "ChatGPT agent mode"; станом на 2026-07-29 офіційна довідка прямо каже, що окремої функції "ChatGPT agent" вже немає — рекомендовано Work. Паралельно окремий агентний браузер Atlas (той самий підхід до керування сторінками — кілька вкладок, завантаження файлів, вхід в акаунти) припиняє роботу 2026-08-09, а ці можливості переносяться в ChatGPT/Codex напряму. **Що це дає для делегування:** та сама ідея, що й «керування браузером» у Claude, — але точне місце, куди ця функція осяде остаточно (Work чи Codex-застосунок), ще не встоялося: перевірити повторно після 9 серпня 2026. **(2026-07-29, help.openai.com — «ChatGPT agent»; «Evolving Atlas into ChatGPT for browser-based agentic work»; openai.com — «Computer-Using Agent», «Introducing Operator»)**
- **`openai/desktop/connectors-apps`** — під'єднані застосунки (те, що раніше називалось "конектори", а з 2026-07-09 — частина каталогу "плагінів"/apps): Google Drive, SharePoint, Dropbox, Box, Outlook, Gmail, Google Calendar, Linear, GitHub, HubSpot, Teams. Після підключення ChatGPT сам підтягує дані з них у розмову й задачі, коли це доречно. **Що це дає для делегування:** так само, як MCP-конектори в Claude — може сам працювати зі сторонніми сервісами, тобто можна доручити регулярне зведення даних з кількох джерел в один звіт без ручного копіювання. **(2026-07-29, help.openai.com — «Apps in ChatGPT»)**
- **`openai/desktop/scheduled-tasks`** — заплановані задачі: одноразові й повторювані (щодня/щотижня/щомісяця), можуть використовувати під'єднані застосунки (наприклад, Gmail); кількість активних задач одночасно обмежена тарифом. **Що це дає для делегування:** аналогічно розкладу Cowork — можна доручити «щоночі зібрати дайджест», хоча знову ж це перекривається наявними launchd-скриптами системи, тож вибір «свій cron чи вбудований розклад ChatGPT» — рішення для кожної механіки окремо. **(2026-07-29, help.openai.com — «Scheduled Tasks in ChatGPT»)**
- Codex app — Codex тепер вбудований у той самий десктоп-застосунок macOS (перемикач ChatGPT/Codex), не окремий інструмент; це десктопний GUI-фронтенд агентного кодування, не плутати з Codex CLI (термінал), який система вже використовує. **(2026-07-29, help.openai.com — «Moving to the new ChatGPT desktop app»; openai.com — «Introducing the Codex app»)**

### Агентні можливості

## Мультимодальність

- **Генерація/аналіз зображень — де межа.** Аналіз зображень (розпізнавання, опис, читання скріншотів/діаграм) доступний у моделях Claude (vision) через звичайний API-виклик — коштує як звичайні токени вводу (зображення переводиться у токени). Це вже достатньо для будь-якої ідеї, що потребує «прочитати скріншот» чи «розібрати діаграму». **(2026-07-28, docs.claude.com — vision)**
- **Генерація зображень (текст → картинка) — Claude не генерує, OpenAI має окремі image-моделі через API.** Claude не генерує зображення. OpenAI пропонує лінійку image-моделей: gpt-image-2 (найновіша), gpt-image-1.5, gpt-image-1, gpt-image-1-mini — усі доступні через API. Вартість: gpt-image-2 за зображення 1024×1024 — від $0.006 (низька якість) до $0.211 (висока якість); є генерація, редагування з масками, мультитурнове уточнення. **Це API для генерації готових зображень за текстовим описом — НЕ файнтюн**: ти не тренуєш власну модель на своїх зображеннях, а просто просиш «намалюй X». Для ідей, де потрібна саме генерація (обкладинки, ілюстрації, маркетингові зображення), цього достатньо. Для ідей, де потрібен файнтюн на конкретному наборі зображень (як PI-0004 dreamlook-тип), — цього НЕ достатньо, бо API не дає тренувати кастомну модель. **(2026-07-29, developers.openai.com/api/docs/guides/image-generation; 2026-07-28 — висновок з відсутності image-generation у Claude)**
- **Файнтюн і інференс дифузійних моделей (Stable Diffusion/SDXL) вимагають GPU-обчислень**, яких немає ні в підписках Claude Code/Codex CLI, ні в базовому наборі M1/M5 (обидва — Apple Silicon без дискретного GPU для важкого ML-навантаження в потрібному для комерційного продукту обсязі). Хмарний GPU під таке навантаження — це окрема стаття регулярних витрат, що типово перевищує поріг €100/міс без окремого погодження. **(2026-07-28, висновок на основі відсутності GPU-хостингу в підписках — підтверджено раніше на прикладі PI-0004)**
- **Аудіо.** Транскрипція мовлення (speech-to-text) доступна локально безкоштовно (розділ «Локальні можливості M1/M5» нижче) — не потребує хмарного API взагалі для помірних обсягів. Генерація мовлення (text-to-speech) та важча/точніша транскрипція — окремі платні API в обох провайдерів, не перевірялись детально в цьому зрізі. **(не підтверджено, перевірити)**
- **Відео.** Аналіз чи генерація відео — не задіяні і не перевірялись у цьому зрізі; жодна з задіяних підписок (Claude Code, Codex CLI) відео не обробляє. **(не підтверджено, перевірити за потреби)**

## Локальні можливості M1/M5

- **Що реально крутиться локально без хмари:** дрібні мовні моделі (кілька мільярдів параметрів) через локальні раннери на кшталт llama.cpp/Ollama — придатно для найпростіших класифікаційних/екстракційних задач без залежності від інтернету чи підписки; embedding-моделі (перетворення тексту в числові вектори для пошуку схожості) — дешево й швидко навіть на M1; локальна транскрипція мовлення (Whisper та подібні моделі) — реально ганяти на M1, ще швидше на M5. **(2026-07-28, загальновідома можливість екосистеми Apple Silicon — не підтверджено окремим офіційним джерелом Anthropic/OpenAI, бо це не їхній продукт; позначити для ревізора як "загальна теза, не з офіційного джерела провайдера")**
- **Де межа.** Навчання (тренування "з нуля" чи важкий файнтюн) великих генеративних моделей — мовних грандового розміру чи дифузійних моделей для зображень — не влазить у можливості M1/M5 в розумний час і без спеціалізованого охолодження/пам'яті; це або вимагає хмарного GPU (стаття витрат понад €100), або взагалі поза межами домашнього заліза. Інференс (просто запуск, не навчання) великих генеративних моделей теж обмежений обсягом оперативної пам'яті типового M1/M5 — практично можна крутити моделі до кількох десятків мільярдів параметрів у квантованому вигляді, не найпотужніші версії. **(2026-07-28, загальна теза, не з офіційного джерела провайдера — позначити для ревізора)**
- M5 — опційний, потужніший: придатний для масової пакетної обробки (наприклад, ніч наскрізь ганяти транскрипти) і локальних embedding у більшому обсязі, лишаючись у межах "без хмари, без нової витрати". **(з PLAN.md, Фаза 6 — інфраструктурне рішення власника, не факт про провайдера)**

## Обмеження й правила

- **Ліміти запитів (рейт-ліміти) на API обох провайдерів** — існують за замовчуванням на нижчих рівнях доступу (rate limits за токенами/хвилину, запитами/хвилину); для системи це найбільш релевантно, якщо колись з'явиться механіка, що ганяє модель на потоці, а не одиничними викликами через підписку. **(2026-07-28, docs.claude.com — Rate Limits; для OpenAI не перевірено окремо в цьому зрізі)**
- **Заборони на автоматизацію в ToS сторонніх платформ** — не властивість самих AI-провайдерів, а окрема категорія ризику для механік-джерел (Reddit, YouTube тощо), уже піднята в PLAN.md (рекомендації рецензії 2026-07-15, п. «yt-dlp і YouTube-транскрипти»). Сюди не входить.
- **Обмеження комерційного використання згенерованого контенту** — правовий статус навчальних даних і згенерованих зображень у генеративних моделях лишається сірою зоною; це вже позначено як відкрите питання в записі PI-0004 (п. 2, «поза межами цієї перевірки»). Якщо колись з'явиться доступна можливість генерації зображень у межах підписки — це питання варто підняти знову перед схваленням будь-якої ідеї на цій основі.
- **Вимоги атрибуції** — не перевірялись окремо для жодного з двох провайдерів у цьому зрізі. **(не підтверджено, перевірити)**
