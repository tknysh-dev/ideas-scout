# ideas-scout

Багатоагентна система автономного пошуку та оцінки можливостей заробітку: моніторить джерела в інтернеті, знаходить ідеї пасивного доходу та (окремим треком) ідеї мобільних застосунків, дедуплікує їх, аналізує за формалізованими критеріями і веде реєстр рішень з умовами повторного перегляду.

Повний план системи — у [`PLAN.md`](./PLAN.md), включно з розділом «Рекомендації рецензії», що коригує структуру нижче.

## Структура репозиторію

Репозиторій ділиться на дві зони: `agents/` — код і конфігурація, що виконується на M1, `dashboard/` — майбутній веб-дашборд (Фаза 3), плюс спільна `shared/` (контракти БД для обох зон) і дані/стан, що мігрують у базу в Фазі 4.

```
agents/
  catalogs/
    ai-capabilities.md        # актуальні можливості AI-провайдерів (веде агент-ревізор)
  criteria/
    criteria-passive-income.md # версіонований чек-лист оцінки для треку доходу
    criteria-apps.md            # чек-лист оцінки для треку застосунків (заглушка)
    availability.md              # ручний сигнал власника: скільки часу/тиждень готовий інвестувати
    taxonomy.md                  # платформний drill-down (трек passive-income)
    search-queries.md            # пакети пошукових запитів
  prompts/                     # провайдер-нейтральні промпти агентів
  scripts/                     # спільні скрипти прогонів, параметризовані треком і провайдером
    telegram-bot.py             # демон-приймальня ручних ідей (long-polling, той самий бот, що шле дайджест)
  launchd/                     # шаблони launchd-плістів (рендеряться install-launchd.sh)
dashboard/                     # майбутній веб-дашборд (Фаза 3), поки порожньо
shared/                        # спільні контракти БД для agents/ і dashboard/
  schema.sql
  contracts.md
registries/
  passive-income/
    ideas/                  # по одному Markdown-файлу на ідею (YAML frontmatter + тіло), трек «пасивний дохід»
  app-ideas/
    ideas/                  # те саме, трек «мобільні застосунки»
inbox/                          # ідеї, надіслані власником у Telegram вручну (вхід агента-тріажу)
logs/
  status/                      # по одному файлу статусу на джоб (last_run, status, errors, token_usage)
  runs/                         # журнали оброблених URL по run_id — для ідемпотентності прогонів
  triage/                       # вердикти ручного тріажу, які бот шле назад у чат
  decisions.md                  # журнал важливих рішень системи
  dedup-decisions.md            # журнал рішень дедуплікації (дублікат/не дублікат) з обґрунтуванням моделі
templates/
  idea.md                       # шаблон запису ідеї (YAML frontmatter + секції тіла)
PLAN.md                          # повний план системи
```

Директорії `registries/`, `logs/`, `inbox/`, `templates/` поки лишаються на корені репозиторію — вони мігрують у базу даних (`shared/schema.sql`) у Фазі 4.

## Примітки

1. Індекси `registries/*/ideas.md` генеруються on-demand зі скрипта і **не комітяться** в репозиторій — щоб уникнути merge-конфліктів у монолітному автогенерованому файлі (рекомендація рецензії, PLAN.md).
2. Секрети (Telegram-токен, API-ключі тощо) у репозиторії **заборонені** — зберігати поза середовищем прогону (Keychain / env), недосяжними для агента.
