# Каталог можливостей AI-провайдерів

**Це базовий зріз від 2026-07-28.** Ведеться агент-ревізор (PLAN.md, Фаза 5, ще не реалізований): 1–2 прогони/тиждень, дельти проти цього зрізу, джерела — лише офіційні (docs.claude.com, anthropic.com/news, сторінка цін Anthropic, платформа/changelog OpenAI, release notes десктоп-застосунків).

**Правило датування:** кожен запис — обов'язково з датою перевірки. Застарілі записи не видаляються, а позначаються `(застаріло, перевірити)` — так ревізор бачить, що саме змінилось, а не лише поточний стан.

**Для чого цей файл:** аналітик звіряє з ним критерій 3 «Реалізовність наявними засобами» (agents/criteria/criteria-passive-income.md) — чи можна побудувати конкретну ідею тим, що вже є (Mac M1 постійно, M5 опційно, підписки Claude Code і Codex CLI), і чи вкладається докупка в поріг €100. Записане тут напряму визначає коди `CAPABILITY_GAP` і `CAPITAL`.

**Рішення власника (2026-07-29, `logs/decisions.md`):** десктоп-застосунки Claude і ChatGPT, встановлені на окремому ізольованому Standard-акаунті macOS на M1 (уже існує), — це цільовий шар **виконання** вже схвалених ідей, а не другорядна деталь. Тому обидва розділи «Десктоп» нижче навмисно ведуть підрозділи з машинним ім'ям (`anthropic/desktop/<тема>` / `openai/desktop/<тема>`), на які записи реєстру посилаються полем `missing_capabilities` — нова десктоп-можливість тут є найімовірнішим тригером ревізора для оживлення `CAPABILITY_GAP`-відхилень (докладніше — `agents/prompts/revisor.md`, `agents/prompts/analyst.md`).

## Anthropic

### API

- **Моделі — актуальна лінійка.** Claude Fable 5 (`claude-fable-5`) — найпотужніша, завжди доступна модель, для найважчих задач і довгих автономних прогонів; Claude Opus 5 (`claude-opus-5`) — основна робоча модель для складного агентного кодування; Claude Sonnet 5 (`claude-sonnet-5`) — баланс якості й ціни, майже на рівні Opus у кодуванні; Claude Haiku 4.5 (`claude-haiku-4-5`) — найшвидша й найдешевша. **(2026-07-28, docs.claude.com — модельний каталог)**
- **Розмір контексту.** У Fable 5, Opus 5 і Sonnet 5 влазить до приблизно мільйона токенів за раз — це десятки тисяч рядків тексту чи коду в одному запиті. У Haiku 4.5 контекст менший — приблизно 200 тисяч токенів. Максимум відповіді (скільки модель може згенерувати за раз) — до 128 тисяч токенів у старших моделей. **(2026-07-28, docs.claude.com)**
- **Ціни за мільйон токенів (вхід/вихід).** Opus 5 — $5 / $25; Sonnet 5 — $3 / $15 (є вступна знижка $2 / $10 до 2026-08-31); Haiku 4.5 — $1 / $5; Fable 5 (найдорожча, найпотужніша) — $10 / $50. Це ціна саме за виклик API — якщо колись механіка буде ганяти модель на потоці поза межами підписки Claude Code, рахунок піде саме за цими тарифами. **(2026-07-28, сторінка цін Anthropic)**
- **Дешевий пакетний режим.** Batch API (запити не потребують миттєвої відповіді) коштує вдвічі дешевше за звичайний виклик — придатний, якщо колись знадобиться масово прогнати багато знахідок через LLM не в реальному часі. **(2026-07-28, docs.claude.com)**
- **Довгий контекст не має надбавки.** У моделей Claude 4.6 і новіших повний мільйонний контекст коштує за тим самим тарифом, що й коротенький запит: запит на 900 тисяч токенів рахується по тій самій ціні за токен, що й на 9 тисяч. Це варте окремої згадки, бо в OpenAI навпаки — там понад певний поріг ціна за токен подвоюється (див. розділ OpenAI нижче). Практично: якщо механіка передбачає щоразу закидати в модель великий масив тексту, у Anthropic це не дає раптового стрибка рахунку. **(2026-08-05, platform.claude.com/docs/en/about-claude/pricing)**
- **Ще одна модель у лінійці — Claude Mythos 5** ($10 / $50 за мільйон токенів, як Fable 5), але з обмеженою доступністю (треба окремо отримувати доступ). Для планування ідей нічого не змінює — просто щоб перелік лінійки вище не виглядав вичерпним, коли він таким не є. **(2026-08-05, platform.claude.com/docs/en/about-claude/pricing)**

### Десктоп

- **`anthropic/desktop/cowork-files`** — Claude Cowork: агентний режим у десктоп-застосунку Claude (окремий продукт від Claude Code, але той самий "двигун" під капотом, без термінала). Здатен довести багатокрокову задачу до кінця самостійно: читати, писати й створювати файли в дозволених теках, перейменовувати пачками, перетворювати купу документів у зведений звіт. Доступно на платних планах (Pro/Max/Team/Enterprise) у Claude Desktop для macOS і Windows (web і мобільна версія — у беті). **Що це дає для делегування:** механіку «зібрати таблицю з кількох джерел» чи «звести пачку файлів у звіт» можна доручити напряму — Claude сам відкриє потрібні файли й доведе задачу до готового документа, без написання окремого скрипта під кожну дрібну задачу. **(2026-07-29, support.claude.com — «Get started with Claude Cowork»)**
- **`anthropic/desktop/computer-use`** — керування комп'ютером у Cowork (дослідницький препрев'ю, тобто рання й нестабільна версія функції): Claude сам клацає мишею, друкує і відкриває довільні застосунки — не лише браузер, — орієнтуючись за скріншотами, так само як людина за екраном. Доступно лише на Pro/Max, лише в десктоп-застосунку macOS/Windows. Умова роботи: Мак має не спати, але Claude може працювати, поки власника немає за екраном. Обмеження: складні задачі часом виконуються лише з другої спроби; повільніше за пряме підключення через API/MCP; чутливі застосунки (банкінг, медичні сервіси, крипто) заблоковано за замовчуванням, можна додати й свій блок-лист. **Що це дає для делегування:** це саме той механізм, що потрібен для «монтажу відео» чи «операцій у браузері» з рішення власника — Claude буквально керує застосунком-редактором чи браузером на екрані M1, а не через окремий API-виклик. **(2026-07-29, support.claude.com — «Let Claude use your computer in Cowork»)**
  - **Керування комп'ютером тепер працює не лише в Cowork, а й у вкладці Claude Code.** Офіційна довідка формулює це дослівно так: доступно «в Cowork і Claude Code у застосунку Claude Desktop для macOS і Windows». Раніше в цьому каталозі було записано, що це можливість самого Cowork — це формулювання неточне й виправлене цим записом. Статус лишається тим самим: дослідницький препрев'ю, лише Pro і Max. Вимога до заліза сформульована так само дослівно: «твій робочий стіл має бути активним — комп'ютер має не спати, а застосунок Claude Desktop бути відкритим», і окремо додано, що «якщо робота стосується фізичної машини, Claude продовжує працювати, поки ти відійшов». **Що це змінює для делегування:** «відійти від Мака» офіційно дозволено — тобто нічний прогін, коли власник спить, а Мак не спить, це підтверджений сценарій, а не здогад. Але «відійти» — це не «заблокувати екран»: про заблокований екран довідка Anthropic так само мовчить (прогалина 5 нижче). Практичний наслідок другої половини новини: механіку, де керування застосунком і робота з кодом переплітаються, більше не треба ділити між двома вкладками — Claude Code сам може клацнути в чужому вікні. **(2026-08-08, support.claude.com — «Let Claude use your computer in Cowork»)**
  - Перевірено повторно: статус не змінився — це й далі дослідницький препрев'ю саме для Pro і Max, і додатково з'ясувалось, що плани Team і Enterprise доступу до керування комп'ютером не мають узагалі. Вимога до заліза лишається тією самою й сформульована дослівно так: комп'ютер має не спати, а застосунок Claude Desktop має бути відкритий. Чи працює це, коли Мак не спить, але екран **заблоковано**, офіційна сторінка так само не каже — на відміну від OpenAI, які на це питання відповіли (див. `openai/desktop/computer-use` нижче). Для нічних безнаглядних прогонів на ізольованому акаунті M1 це поки що незакрите питання саме на боці Claude. **(2026-08-05, support.claude.com — «Let Claude use your computer in Cowork»)**
- **`anthropic/desktop/mcp-connectors`** — MCP-конектори у Cowork: підключення сторонніх сервісів (Google Calendar, Slack, GitHub, Linear, Notion тощо) або в один клік як готовий "конектор", або вручну через довільний MCP-сервер. **Що це дає для делегування:** може сам працювати з файлами і сторонніми сервісами — тобто йому можна доручити, скажімо, регулярне складання таблиці з даних кількох джерел (звести нотатки з Notion і задачі з GitHub в один звіт), без ручного зведення вручну. **(2026-07-29, support.claude.com — «Use connectors to extend Claude's capabilities»)**
- **`anthropic/desktop/scheduled-tasks`** — заплановані задачі в Cowork: задачу можна поставити на повторення за розкладом. Локальні сесії (ті, що працюють з файлами чи браузером просто на самому Маку) виконуються лише поки Мак не спить і застосунок відкритий — пропущений через сон запуск виконується одразу після пробудження. Віддалені сесії (без потреби в локальних ресурсах Мака) крутяться на серверах Anthropic і працюють, навіть коли Мак спить чи застосунок закритий. **Що це дає для делегування:** механіку «щоночі зібрати звіт» можна доручити напряму вбудованому розкладу Cowork — але для задач, які не потребують саме локального Мака, це вже частково перекриває наявну систему launchd-скриптів (`docs/operations.md`), тож вибір «свій cron чи вбудований розклад Cowork» — окреме рішення для кожної механіки. **(2026-07-29, support.claude.com — «Schedule recurring tasks in Claude Cowork»; «Claude Cowork architecture overview»)**
  - **Розклад став придатним для роботи без людини — виправлено три поломки, які раніше цьому заважали.** У версії застосунку від 4 серпня 2026 полагодили: (1) кнопку «Дозволити для всіх запусків за розкладом», яка з'являлась там, де вибір насправді не зберігався, — через це задача питала дозволу щоразу заново, тобто нічний запуск просто зупинявся й чекав людини; (2) розклад із записом «7» для неділі, який не спрацьовував ніколи; (3) зависла задача, яка далі крутилась у фоні, поки застосунок не перезапустять. Ще раніше, у тій самій серії виправлень, прибрали дублювання: після пробудження комп'ютера пропущені запуски вистрілювали пачкою одночасно. **Що це змінює:** до цього вбудований розклад Cowork не можна було всерйоз розглядати як заміну launchd-джобам для безнаглядної роботи — він упирався в повторний запит дозволу. Тепер це вже питання вибору, а не технічної перешкоди. **(2026-08-05, claude.com/docs/cowork/changelog — версія v1.25927.0 від 2026-08-04)**
- **`anthropic/desktop/cloud-sessions`** — сесії Cowork у хмарі: робота виконується на серверах Anthropic, а не на твоєму комп'ютері, сесії й файли зберігаються в акаунті Claude. Дослівне формулювання довідки: «закрий ноутбук — і Claude працює далі», «задачі за розкладом виконуються без жодного пристрою онлайн». Але є суттєве обмеження, яке легко проґавити: хмарна сесія може читати й писати файли в підключених теках на твоєму комп'ютері **лише поки на тому комп'ютері відкритий десктоп-застосунок**. Тобто «працює без Мака» стосується лише тих задач, яким локальні файли не потрібні. Доступність: на вебі й мобільному Cowork у беті для Max, Team і Enterprise, на Pro викочується протягом наступних тижнів. **Що це дає для делегування:** механіку, яка живе цілком у хмарі (зібрати з вебу, звести, надіслати), можна ставити на розклад і не тримати M1 увімкненим; механіку, яка чіпає локальні файли на M1, — не можна, для неї Мак усе одно має не спати з відкритим застосунком. **(2026-08-05, support.claude.com — «Use Claude Cowork on web, desktop, and mobile»)**
- **`anthropic/desktop/permission-modes`** — три режими дозволів регулюють, наскільки без нагляду діє Claude: Manual (питає перед кожною дією), Auto (діє без питань, але блокує чутливі дії — доступ до нових тек, видалення файлів, створення розкладу), Skip (не питає й нічого не перевіряє автоматично). **Що це дає для делегування:** це і є регулятор ризику для ізольованого акаунта M1 — режим Skip потрібен саме для «без людини біля екрана», але він же найризикованіший, тож для кожної делегованої механіки варто явно вирішувати, який режим прийнятний. **(2026-07-29, support.claude.com — «Use Claude Cowork safely»)**
  - **Дозволи стали дрібнішими — і в один бік послабились, і в інший затягнулись.** Три зміни у версії застосунку від 6 серпня 2026: (1) вибраний режим дозволів тепер діє на ту теку, де ти його вибрав, а не стає загальною установкою на всю машину — тобто ризикований режим можна тримати ввімкненим рівно там, де крутиться делегована механіка, не відкриваючи його для всієї роботи на Маку; (2) з'явився режим теки «тільки читати» (ключ налаштувань `allowedWorkspaceFolders`, значення `mode: ro`): Claude бачить і шукає у теці, але писати в неї не може — змінені копії кладе в теку результатів сесії. Важлива дрібним шрифтом розписка: у вкладці Claude Code це стримує лише власні файлові інструменти Claude, а команди в терміналі (Bash) і сесії SSH цього обмеження поки що не дотримуються, тобто «тільки читати» там не є герметичним. (3) Навпаки затягнули: кнопку «завжди дозволяти» прибрали для запуску dev-сервера в панелі Browser — тепер кожен запуск питає окремо, і сервер, який упав, питає знову замість тихого перезапуску. Плюс перед тим, як посилання з живого артефакту відкриється в браузері, тепер з'являється підтвердження (з опцією «більше не питати» для конкретного сайту). **Що це змінює для делегування:** режим «тільки читати» — це готовий запобіжник для механік, які мають лише читати чужі дані (скажімо, розбирати теку з вивантаженнями), і його варто ставити за замовчуванням замість повного доступу. А от механіка, яка сама піднімає dev-сервер у панелі Browser, безнаглядно вночі більше не проходить — там знову з'явився ручний клік. **(2026-08-08, claude.com/docs/cowork/changelog — версія v1.26832.0 від 2026-08-06)**
- Claude Code desktop — той самий "двигун", що й Cowork, але фронтенд під код (термінал, git-діфи прямо в застосунку) замість некодових задач; технічний бік (headless-режим `claude -p`) уже описано в розділі «Агентні можливості» нижче. Для десктоп-делегування важливе саме розмежування: Cowork — для «зроби мені файл/звіт/таблицю», Claude Code desktop — для «внеси мені зміну в код». **(2026-07-29, claude.com — «Navigating the Claude desktop app: Chat, Claude Cowork, Claude Code»)**
  - **Сесія Claude Code тепер сама відновлюється після засинання комп'ютера** — раніше сон Мака посеред роботи обривав сесію, тепер вона продовжується автоматично, а якщо продовжити безпечно не можна, з'являється банер із кнопкою «Continue» і пропозицією доробити сесію в хмарі. Окремо полагодили перезапуск застосунку на оновлення, який перебивав задачу Claude Code чи Cowork просто посеред виконання. **Що це змінює:** вимога «Мак не спить» лишається чинною для керування комп'ютером, але для звичайної роботи Claude Code випадковий сон машини вже не означає загублений прогін. **(2026-08-05, claude.com/docs/cowork/changelog — версія v1.25927.0 від 2026-08-04)**
  - **Полагоджено накопичення сміття, яке з часом валило нові сесії.** Робочі теки завершених сесій Claude Code лишались на диску й накопичувались, поки нова сесія не падала з помилкою «немає місця на диску»; тепер вони прибираються. Окремо: вікна сесій, відкриті на момент виходу із застосунку, тепер самі відкриваються при наступному запуску. **Що це змінює:** для механіки, яка запускає сесію щоночі місяцями поспіль, це та різниця між «працює постійно» і «працює, поки хтось раз на місяць не почистить диск» — тобто одна зі схованих вимог до людської підтримки зникла. **(2026-08-08, claude.com/docs/cowork/changelog — версія v1.26832.0 від 2026-08-06)**

### Агентні можливості

- **Робота з інструментами (tool use).** Claude вміє викликати визначені розробником функції (кастомні tools) і вбудовані серверні інструменти — пошук в інтернеті (`web_search`), завантаження сторінки за URL (`web_fetch`), виконання коду в ізольованому контейнері (`code_execution`), робота з файлами. Це саме те, на чому побудовані збирач і аналітик системи. **(2026-07-28, docs.claude.com — Tool Use overview)**
- **MCP (Model Context Protocol).** Claude Code вміє підключати зовнішні джерела даних та інструменти через MCP-сервери (наприклад, доступ до браузера, Linear, файлових ресурсів) — саме так цей інструмент сам підключений до Chrome, iOS-симулятора, Linear тощо в поточному середовищі. **(2026-07-28, docs.claude.com)**
- **Тривалі автономні прогони.** Claude Code підтримує headless-режим (`claude -p` — прогін без інтерактивного діалогу, разовий виклик з промптом) — саме такий режим потрібен для запуску збирача й аналітика через launchd/cron без участі людини. Є task budgets (бюджет токенів на задачу, щоб агент сам розрахував темп роботи і не обірвався на півслові) і компакція контексту (автоматичне стиснення історії розмови, коли вона наближається до ліміту вікна). **(2026-07-28, docs.claude.com — Claude Code, Task Budgets, Compaction)**
- **Керування комп'ютером (computer use).** Claude вміє робити скріншоти та керувати мишею/клавіатурою — може імітувати людину в браузері. Технічно доступно, але в цій системі не заплановане (збирач працює через RSSHub/скрапінг, а не через візуальне керування браузером). **(2026-07-28, docs.claude.com)**

### Ліміти підписок

- **Claude Code — ліміти на підписці, не на прогін.** Підписка Claude (Pro/Max) дає обмежену кількість використання за ковзне вікно (типово 5-годинне вікно плюс тижневий ліміт) — не пряму оплату за токен, а квоту повідомлень/токенів у часі. Headless-прогони (`claude -p`) споживають ту саму квоту, що й інтерактивна робота — це критично для системи: якщо власник активно працює в Claude Code вдень, а джоби збирача/аналітика йдуть вночі, вони діляться одним пулом ліміту підписки. **(2026-07-28, docs.claude.com — не підтверджено остаточно, чи headless-прогони мають окремий облік від інтерактивних; перевірити окремо)** *(частина про «не підтверджено» застаріла з 2026-08-05 — див. наступний запис)*

Захист робочих годин у `agents/criteria/availability.md` (вікно 07:00–20:00, коли автопрогони не запускаються) — це не перестраховка, а єдиний наявний механізм розведення. **(2026-08-05, support.claude.com — «How do usage and length limits work?»; «Models, usage, and limits in Claude Code»)**

Тижневий ліміт скидається у фіксований час тижня, закріплений за акаунтом. **Що це означає:** якщо колись доведеться підняти тариф через нічні прогони, планувати треба обидві стелі — можна впертись у тижневу межу по Sonnet, не вичерпавши загальної. **(2026-08-05, support.claude.com — «What is the Max plan?»)**

### Десктоп

**Важливий контекст датування:** 2026-07-09 OpenAI об'єднав десктоп-застосунок macOS — Chat, Work і Codex тепер один застосунок (стара версія лишилась окремо як "ChatGPT Classic"); одночасно офіційна довідка більше не описує окрему функцію "ChatGPT agent" — замість неї рекомендовано ChatGPT Work. Тобто станом на 2026-07-29 «агентний режим» ChatGPT — це Work, а не окрема кнопка з назвою Agent. Окремо, агентний браузер-застосунок Atlas планово припиняє роботу 2026-08-09 — його браузерні агентні можливості переносяться напряму в ChatGPT/Codex. **(2026-07-29, help.openai.com — «Moving to the new ChatGPT desktop app»; «Evolving Atlas into ChatGPT for browser-based agentic work»)**

- **`openai/desktop/work-mode`** — ChatGPT Work: агентний режим для довгих багатокрокових задач — шукає інформацію, працює через під'єднані застосунки й файли, доводить справу до готового документа/таблиці/презентації/сайту, лишаючись над проєктом годинами й самостійно розбиваючи його на кроки, з можливістю стежити за прогресом і схвалювати важливі дії по дорозі. Доступність за тарифом: Pro/Pro Lite/Enterprise/Edu отримали першими, Plus і Business — слідом; на Free і Go Work недоступний. **Що це дає для делегування:** прямий аналог того, що власник хоче доручати десктоп-агенту — «склади таблицю з кількох джерел», «зроби звіт», «постав сайт-трекер» — без написання скрипта самому. **(2026-07-29, help.openai.com — «ChatGPT Work and Codex»; openai.com — «ChatGPT is now a partner for your most ambitious work»)**
- **`openai/desktop/computer-use`** — керування комп'ютером у ChatGPT: підтверджено офіційно, що ChatGPT бачить і керує звичайними віконними застосунками на macOS і Windows — клацає, друкує, ходить по інтерфейсу тих застосунків, які ти йому дозволив, — а не лише браузером і під'єднаними сервісами. Доступно в **ChatGPT Work і в Codex** у десктоп-застосунку (у підтримуваних регіонах). Що для цього потрібно на Маку: видати два системні дозволи — Screen Recording (щоб ChatGPT бачив вікно застосунку) і Accessibility (щоб міг клацати й друкувати). Три речі, важливі саме для безнаглядної роботи на M1:
  1. **Працює у фоні.** На macOS керування комп'ютером може виконуватись у фоні, поки ти сам працюєш в інших застосунках — з маленьким прев'ю активного вікна «картинка в картинці». (На Windows навпаки: там воно займає активний робочий стіл і у фоні паралельно з твоєю роботою не працює.)
  2. **Є режим роботи при заблокованому екрані.** За замовчуванням Мак має бути притомний і розблокований, але окремо вмикається режим, у якому керування продовжує працювати після того, як Мак заблокувався. Це саме те, чого бракує на боці Claude, — там офіційна довідка вимагає, щоб комп'ютер не спав і застосунок був відкритий, і про заблокований екран мовчить.
  3. **Чого воно не вміє за задумом:** не автоматизує термінальні застосунки і сам ChatGPT (бо через них можна було б обійти його ж захисні правила), не може автентифікуватись як адміністратор і не натискає системні запити дозволів на безпеку й приватність.
  Офіційна документація не називає цю можливість бетою чи препрев'ю — на відміну від аналога в Claude Cowork.
  - Перевірено повторно 2026-08-08: усе перелічене вище лишилось без змін. Додалась одна деталь, важлива саме для механік «зайди в мій акаунт на чужому сайті»: коли ChatGPT працює через браузер, він взаємодіє зі сторінками, **де ти вже увійшов**, і сайт вважатиме ці дії діями від твого імені й твого акаунта. Тобто «увійти замість тебе» він не вміє, а «діяти в уже відкритій твоїй сесії» — вміє, з усією відповідальністю за наслідки на тобі. Це не закриває потреби в автономній роботі з цифровим сертифікатом (див. записи реєстру з `*/desktop/authenticated-portal-sessions`): сертифікат і системні запити безпеки лишаються поза межами — довідка й далі прямо каже, що керування комп'ютером не автентифікується як адміністратор і не натискає системні запити дозволів. **(2026-08-08, learn.chatgpt.com/docs/computer-use)** **Що це дає для делегування:** для механік, де виконання — це «клацай в чужому застосунку на моєму Маку», OpenAI зараз дає помітно міцнішу основу за Anthropic: фон, робота при заблокованому екрані і статус звичайної функції замість дослідницького препрев'ю. Але зверни увагу на дві розписки в дрібному шрифті: потрібні системні дозволи Screen Recording і Accessibility (те саме, що потрібне й Claude, — див. прогалину про співіснування двох застосунків на одному акаунті нижче), і термінал під це керування навмисно не підпадає. **(2026-08-05, learn.chatgpt.com/docs/computer-use)**
- **`openai/desktop/browser-agent-transition`** — керування браузером зараз у перехідному стані між продуктами: колишній Operator (окремий продукт 2025) керував браузером через аналіз скріншотів (модель "Computer-Using Agent"), потім це влилося в "ChatGPT agent mode"; станом на 2026-07-29 офіційна довідка прямо каже, що окремої функції "ChatGPT agent" вже немає — рекомендовано Work. Паралельно окремий агентний браузер Atlas (той самий підхід до керування сторінками — кілька вкладок, завантаження файлів, вхід в акаунти) припиняє роботу 2026-08-09, а ці можливості переносяться в ChatGPT/Codex напряму. **Що це дає для делегування:** та сама ідея, що й «керування браузером» у Claude, — але точне місце, куди ця функція осяде остаточно (Work чи Codex-застосунок), ще не встоялося: перевірити повторно після 9 серпня 2026. **(2026-07-29, help.openai.com — «ChatGPT agent»; «Evolving Atlas into ChatGPT for browser-based agentic work»; openai.com — «Computer-Using Agent», «Introducing Operator»)**
  - Питання «Work чи Codex» тепер має відповідь, і вона — «обидва»: документація керування комп'ютером називає ChatGPT Work і Codex рівноправними місцями, де ця функція живе, а браузер там просто один із застосунків, якими агент керує (див. `openai/desktop/computer-use` вище). Тобто окремої кнопки «керування браузером» більше немає — є загальне керування застосунками, і браузер під нього підпадає. Дату вимкнення Atlas (2026-08-09) на момент цієї перевірки ще не пройдено, тож перевірку після неї варто повторити — але вже не заради того, «куди осяде функція», а заради того, чи не загубилось при переїзді щось специфічно браузерне (вкладки, вхід в акаунти, завантаження файлів). **(2026-08-05, learn.chatgpt.com/docs/computer-use)**
- **`openai/desktop/connectors-apps`** — під'єднані застосунки (те, що раніше називалось "конектори", а з 2026-07-09 — частина каталогу "плагінів"/apps): Google Drive, SharePoint, Dropbox, Box, Outlook, Gmail, Google Calendar, Linear, GitHub, HubSpot, Teams. ## Мультимодальність

- **Генерація/аналіз зображень — де межа.** Аналіз зображень (розпізнавання, опис, читання скріншотів/діаграм) доступний у моделях Claude (vision) через звичайний API-виклик — коштує як звичайні токени вводу (зображення переводиться у токени). Це вже достатньо для будь-якої ідеї, що потребує «прочитати скріншот» чи «розібрати діаграму». **(2026-07-28, docs.claude.com — vision)**
- **Генерація зображень (текст → картинка) — Claude не генерує, OpenAI має окремі image-моделі через API.** Claude не генерує зображення. OpenAI пропонує лінійку image-моделей: gpt-image-2 (найновіша), gpt-image-1.5, gpt-image-1, gpt-image-1-mini — усі доступні через API. Вартість: gpt-image-2 за зображення 1024×1024 — від $0.006 (низька якість) до $0.211 (висока якість); є генерація, редагування з масками, мультитурнове уточнення. **Це API для генерації готових зображень за текстовим описом — НЕ файнтюн**: ти не тренуєш власну модель на своїх зображеннях, а просто просиш «намалюй X». Для ідей, де потрібна саме генерація (обкладинки, ілюстрації, маркетингові зображення), цього достатньо. Для ідей, де потрібен файнтюн на конкретному наборі зображень (як PI-0004 dreamlook-тип), — цього НЕ достатньо, бо API не дає тренувати кастомну модель. **(2026-07-29, developers.openai.com/api/docs/guides/image-generation; 2026-07-28 — висновок з відсутності image-generation у Claude)** *(доповнено 2026-08-08: висновок про файнтюн не просто лишається чинним — з травня 2026 OpenAI взагалі закриває платформу файнтюну для нових користувачів, див. розділ «OpenAI → API» вище. ## Локальні можливості M1/M5

- **Що реально крутиться локально без хмари:** дрібні мовні моделі (кілька мільярдів параметрів) через локальні раннери на кшталт llama.cpp/Ollama — придатно для найпростіших класифікаційних/екстракційних задач без залежності від інтернету чи підписки; embedding-моделі (перетворення тексту в числові вектори для пошуку схожості) — дешево й швидко навіть на M1; локальна транскрипція мовлення (Whisper та подібні моделі) — реально ганяти на M1, ще швидше на M5. **(2026-07-28, загальновідома можливість екосистеми Apple Silicon — не підтверджено окремим офіційним джерелом Anthropic/OpenAI, бо це не їхній продукт; позначити для ревізора як "загальна теза, не з офіційного джерела провайдера")**
- **Де межа.** Навчання (тренування "з нуля" чи важкий файнтюн) великих генеративних моделей — мовних грандового розміру чи дифузійних моделей для зображень — не влазить у можливості M1/M5 в розумний час і без спеціалізованого охолодження/пам'яті; це або вимагає хмарного GPU (стаття витрат понад €100), або взагалі поза межами домашнього заліза. Інференс (просто запуск, не навчання) великих генеративних моделей теж обмежений обсягом оперативної пам'яті типового M1/M5 — практично можна крутити моделі до кількох десятків мільярдів параметрів у квантованому вигляді, не найпотужніші версії. **(2026-07-28, загальна теза, не з офіційного джерела провайдера — позначити для ревізора)**
- M5 — опційний, потужніший: придатний для масової пакетної обробки (наприклад, ніч наскрізь ганяти транскрипти) і локальних embedding у більшому обсязі, лишаючись у межах "без хмари, без нової витрати". **(з PLAN.md, Фаза 6 — інфраструктурне рішення власника, не факт про провайдера)**

## Обмеження й правила

- **Ліміти запитів (рейт-ліміти) на API обох провайдерів** — існують за замовчуванням на нижчих рівнях доступу (rate limits за токенами/хвилину, запитами/хвилину); для системи це найбільш релевантно, якщо колись з'явиться механіка, що ганяє модель на потоці, а не одиничними викликами через підписку. **(2026-07-28, docs.claude.com — Rate Limits; для OpenAI не перевірено окремо в цьому зрізі)**
- **Рейт-ліміти OpenAI — з числами, і одне з них збігається з твоїм порогом.** Доступ ділиться на п'ять рівнів, і рівень визначається тим, скільки ти вже сплатив: Tier 1 — після $5 сплачено, і місячна стеля витрат на ньому **$100**; Tier 2 — $50 сплачено, стеля $500; Tier 3 — $100, стеля $1000; Tier 4 — $250, стеля $5000; Tier 5 — $1000, стеля $200 000. Рівень підвищується автоматично в міру витрат. Ліміти за хвилину залежать від моделі; для найдешевшої Luna на Tier 1 це 500 запитів і 500 тисяч токенів на хвилину, далі до 5000 запитів / 2 млн токенів на Tier 2. **Що це означає практично:** дві приємні новини й одна пастка. Перша: 500 запитів на хвилину на найнижчому рівні — це з великим запасом більше, ніж потрібно будь-якій механіці з цього реєстру, тож рейт-ліміт як причина відмови майже напевно не спрацює. Друга: стеля Tier 1 у $100/міс майже точно збігається з твоїм порогом €100 — тобто новий API-акаунт фізично не дасть витратити більше, ніж ти й так дозволив, і це безкоштовний запобіжник від рахунку-сюрпризу. Пастка ж у тому, що це стеля, а не бюджет: механіка, яка впреться в неї 20-го числа, просто перестане працювати до кінця місяця, і це треба закладати в розрахунок як режим відмови. **(2026-08-08, developers.openai.com/api/docs/guides/rate-limits; developers.openai.com/api/docs/models/gpt-5.6-luna)**
- **Заборони на автоматизацію в ToS сторонніх платформ** — не властивість самих AI-провайдерів, а окрема категорія ризику для механік-джерел (Reddit, YouTube тощо), уже піднята в PLAN.md (рекомендації рецензії 2026-07-15, п. «yt-dlp і YouTube-транскрипти»). Сюди не входить.
- **Обмеження комерційного використання згенерованого контенту** — правовий статус навчальних даних і згенерованих зображень у генеративних моделях лишається сірою зоною; це вже позначено як відкрите питання в записі PI-0004 (п. 2, «поза межами цієї перевірки»). Якщо колись з'явиться доступна можливість генерації зображень у межах підписки — це питання варто підняти знову перед схваленням будь-якої ідеї на цій основі.
- **Вимоги атрибуції** — не перевірялись окремо для жодного з двох провайдерів у цьому зрізі. **(не підтверджено, перевірити)**
